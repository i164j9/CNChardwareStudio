What this app does

The Studio runs engineering formulas in blocks. A block takes numeric inputs and displays a result. You can connect a later block to an earlier result with a pipe, making a simple calculation pipeline. You can also graph how a result changes as an input changes, compare compatible graphs in a master chart, use reference charts, and convert common units. The math library is metric-first unless the selected formula or an input label says otherwise.

Recommended workflow: from question to checked result

  1. Write down the question. For example: “What is the axis resolution?”, “How much screw torque is needed for this thrust?”, or “How much current does this load draw?”
  2. Collect the source values first. Prefer motor, drive, screw, belt, power-supply, and machine documentation over guesses. Record each value with its unit and whether it is a maximum, typical, RMS, peak, input, or output rating.
  3. Pick the smallest formula that answers the question. Read its plain-language description and every input hint. If the units or meaning of a value do not match, convert it before entering it.
  4. Enter and check one result at a time. The result updates immediately. Confirm that it has a sensible order of magnitude and the expected unit before building a longer chain.
  5. Connect only values that genuinely depend on each other. Use Pipe for a calculated result; leave independent inputs as direct values. Keep the producer block above its users.
  6. Vary uncertain values. Use a graph sweep to see sensitivity to one input, or compare a few plausible values manually. A curve can reveal whether a small assumption change matters.
  7. Cross-check important answers. Compare with a second calculation, manufacturer data, measured behavior, or an independent engineering check. Check all assumptions and units before acting on the result.
  8. Save a useful setup. Give results recognizable names, add brief notes where helpful, and download the pipeline JSON so the same assumptions can be reviewed later.

A good calculation is traceable: another person should be able to see where each input came from, which unit it uses, what the formula assumes, and how the answer was checked.

Offline use

Styling is bundled in the local cncHardwareStyles.css file; the pages no longer fetch Tailwind from a CDN. Keep that CSS file and cncHardwareMath.js beside the HTML files. For browsers that restrict JavaScript modules opened with a file:// URL, launch the folder using a local web server such as VS Code Live Server. Once the files and local server are available, the app does not need internet access.

Developers can rebuild the stylesheet after changing utility classes with npm install and npm run build:css. The generated CSS is already included for normal use.

Understand a formula block

Each card is one calculation. Its top row identifies the block, lets you choose a formula, and provides result, graph, and delete controls. The description below the formula name explains the calculation. Input fields have a label and, where useful, a short help hint. The result is shown at the bottom of the card.

Result name

This is the name other blocks see in their Pipe menus and the reusable-results list. Keep names unique and descriptive, such as SpindleCurrent or AxisTorque. Use letters, numbers, and underscores.

Display unit

Some results offer a unit selector. It changes how the answer is displayed, not its underlying value or the value sent through a Pipe. Select the scale that is easiest to read.

Graph (advanced)

Enable this to show parameter-sweep controls and an individual chart when that formula supports graphing. It can also make the chart available to the Pipeline Graphs gallery and compatible master charts.

Delete

The × button removes the card. Check later blocks afterward: any inputs that used its output may need to be connected to another producer or changed back to a direct value.

Choose a calculation

Add a block and use its Calculate menu. The menu uses plain-language names rather than requiring you to know the internal formula name. Start with the quantity you need to find, then use the description and input guidance to confirm you have the right formula. Do not select a formula only because its name contains a familiar word: similar quantities can have different definitions or assumptions.

Units and reliable inputs

The Studio calculates with the units expected by each selected formula; it does not automatically recognize a unit typed beside a number. The input label and its help hint are the source of truth. For example, 1 millimeter, meter, henry, or millihenry are very different values. Convert first, then enter the numeric value in the required unit.

  • Use metric/SI units as the default: meters, kilograms, newtons, newton-meters, watts, volts, amps, ohms, henries, farads, hertz, and seconds where requested.
  • Pay attention to prefixes: m is milli (10⁻³), while µ is micro (10⁻⁶). For example, 5 mH is 0.005 H and 200 µF is 0.0002 F.
  • Confirm whether an electrical nameplate value is RMS or peak. Most AC equipment and meters report RMS; peak-value helpers are explicit.
  • Distinguish a total system value from a per-motor or per-phase value. Check whether a three-phase input expects line-to-line voltage, line current, or total real power.
  • Use positive, physically meaningful values where required. Zero, negative, or impossible values can produce an error or a mathematically valid but useless answer.
  • Use the quick unit converter for reference conversions, but remember that it does not alter block inputs or insert a conversion into the pipeline.

Create and configure a block

  1. Open the calculator and choose Add Formula Block.
  2. Choose what you want to calculate from the plain-language dropdown at the top of the block. The short description below it explains what the calculation does.
  3. Enter a number for each input. The result recalculates as you edit values.
  4. Read the note below each input for what it means and which units to use.
  5. Use the Value / Pipe selector to enter a value directly or reuse an earlier block’s output.
  6. Change the output variable name if you want a more descriptive label in the ledger.

Inputs start at zero. Many formulas require positive values, so a block can show an error until you enter valid inputs. Hover over “Error” to see the formula’s error message.

Example: calculate steps per millimeter

For a 200-step motor, 16× microstepping, a 2 mm belt pitch, and a 20-tooth pulley, select stepperPureBeltStepsPerMm and enter:

InputValue
motorSteps200
microstepping16
beltPitch2
pulleyTeeth20

The result is 80 steps/mm. This is a calibration estimate from the entered mechanical dimensions; verify it against the actual machine.

Calculate straightness error from measurements

Choose Straightness error over the measured length or Straightness error scaled to 500 mm. Enter the distance between the first and last measurement points, then type the measured readings in order from start to end as a comma-separated list in micrometers (µm). Include both end readings and take all readings at equally spaced points. For example, readings of 0, 10, 20, 30, 31 over 350 mm produce about 6.75 µm of end-to-end straightness error, or 9.64 µm per 500 mm when scaled.

Turn on Graph to see a spreadsheet-style plot: the horizontal axis is position along the measured length, and the vertical axis is the reading in micrometers. The blue line shows your readings; the dashed orange line joins the first and last readings. The straightness result is the full high-to-low range of the differences between those two lines.

This calculation compares each reading with a straight line joining the first and last readings. It is an end-to-end reference method, not a minimum-zone straightness measurement under a specific inspection standard.

Understand parameter-sweep graphs

For other calculations, a parameter-sweep graph changes one chosen input from its start value to its end value and recalculates the result at each point. All other inputs stay as entered in the formula block. The horizontal axis is the input being varied; the vertical axis is the calculated result. Increase the number of points for a smoother-looking curve. If another enabled graph uses the same input, start and end values, and point count, the app automatically adds both results to a combined master chart. Different result units use separately labeled vertical axes. Invalid calculations in the selected range are left out and reported below the graph.

Use a sweep to answer “what changes if this one input changes?” Keep the other inputs fixed at representative values, and choose a range that covers plausible operating conditions rather than arbitrary extremes. The chart is not a time history: points show formula results for input values, not how the machine moves through time. It also does not optimize the result or choose a safe range for you.

Use the hardware reference charts

The angle chart answers: “If this arm or shaft turns a little, how far does a point on it move?” Enter the distance from the center to that point, the angle difference in degrees or arcseconds, and how long the movement takes. Choose the output scale in SI units. For example, a point 1 m from the center shifts about 4.848 µm for a 1 arcsecond angle difference. Changing the radius between millimeters and inches keeps the physical distance the same.

The time also gives an estimated average speed and a chart of movement over time. This simple chart assumes steady speed from start to finish; real machines may accelerate and slow down, so it is not a motion profile or a safety limit.

The axis chart shows how many motor steps or servo encoder counts are needed to move a certain distance. Choose the motor and drive that match your machine, then enter the values from your motor, screw, belt, and pulley documentation. Metric units are selected by default; switching to inches converts the displayed travel range.

Both charts update as you change settings. They are reference estimates: use the machine’s actual motor, transmission, screw lead, belt pitch, and pulley specifications for meaningful results.

Direct-drive screw resolution

For a motor coupled directly to a screw, use stepperDirectScrewStepsPerMm or servoDirectScrewCountsPerMm. Enter the screw lead in millimeters per revolution. The servo formula converts encoder pulses to quadrature counts using 4× decoding.

Connect blocks with a pipe

Add another block after the first. Its Pipe dropdown can select outputs from earlier blocks. For example, pipe an earlier DC current result into the current input of dcPowerWatts, then enter a voltage in the other input. The ledger lists the current outputs and their values.

Blocks run from top to bottom. Only outputs from blocks above the current block are available, so arrange a producer before the block that uses its result.

  1. Add the calculation that produces a value. Give its result a recognizable name.
  2. Add the calculation that needs that value below the producer.
  3. On the correct input row, change Value to Pipe, then choose the producer’s named result.
  4. Leave the other inputs as direct values unless they also come from calculations.
  5. Check the result and unit after connecting the pipe. The later block recalculates when the upstream result changes.

When blocks are connected by pipes, the Studio automatically puts them in a Related calculations group. A block whose result feeds several later calculations is marked Shared foundation; this makes branching calculation paths easier to follow. The group changes automatically when you change a Pipe source or remove a connection or block. Role labels show whether a block is a foundation, a shared foundation, or a block that uses or feeds another result. These labels describe connections, not engineering importance or correctness.

A Pipe passes the producer’s calculated value in its original internal unit. Changing the producer’s display-unit selector does not convert that value for the next formula. Connect only compatible quantities: a number alone does not carry a unit conversion or dimensional check into the next block. If a needed output is not listed, make sure the producer is above the consumer, has a result name, and has not been deleted.

Set a result name before connecting other blocks when possible. If you rename a result that is already used by downstream blocks, reselect the producer in each affected Pipe menu.

The computed result shows its measurement unit. Where conversions are available, use the unit dropdown beside the result to change the displayed scale; metric units are selected by default. This affects display only: piped values remain in the formula’s original units, so downstream calculations are unchanged.

Use the quick unit converter

At the bottom of the Studio, choose a conversion type, enter a value, and select its input unit. The table shows the equivalent in every listed unit. It includes length, mass, area, volume, temperature, angle, speed, force, torque, pressure, and electrical units such as voltage, current, resistance, power, frequency, capacitance, and inductance. Fuel-economy conversions are not included. This reference converter does not change the values used by calculation blocks.

Graph a parameter sweep

  1. Turn on 📊 Graph Sweep in a formula block.
  2. Choose which numeric input to sweep. The graph recalculates the formula at each sample.
  3. Set the minimum and maximum for that input, then choose a sample count from 2 to 500.
  4. All other inputs stay at their current literal values or piped results.

The horizontal axis is the selected input and the vertical axis is the formula result. Invalid samples (for example, values outside a formula’s valid domain) are omitted and reported beneath the graph. The graph updates as pipeline inputs change and is saved with the block when you export JSON.

The thrust-to-torque formula defaults to sweeping 0–2,500 N in 100 N increments. The reflected-load inertia formula defaults to sweeping gantry mass from 5–150 kg in 5 kg increments. Both presets can be adjusted. The torque graph shows required motor torque, not the motor’s holding-torque rating.

The sweep controls are Value to vary, the start and end of the range, and the number of samples. Two samples show only the endpoints; more samples reveal curve shape but take longer to calculate. The graph uses evenly spaced input values between the endpoints. Keep the selected input within the formula’s meaningful range and check any status message about omitted invalid samples.

Other common sweep inputs also start with convenient ranges: frequency (10–1,000 Hz), inductance (0.5–10 mH or 0.001–0.1 H, depending on the formula’s units), steps or counts per millimeter (10–2,000), and rotational speed (0–3,000 rpm). These are starting points, not hardware limits; change the range to match the system being analyzed.

When graphing reflected linear-load inertia, the Studio also plots inertial torque against reflected inertia and overlays reflected inertia and inertial torque against gantry mass on separate vertical scales. The same block also estimates torque-producing motor current and DC bus current through a simplified acceleration/deceleration cycle. Enter the motor torque constant (N·m/A), DC bus voltage, motor/drive efficiency, and acceleration and deceleration durations. Choose either linear axis acceleration (m/s²), converted using screw lead and gear ratio, or motor angular acceleration (rad/s²), converted back to linear acceleration for the annotation.

Inertial torque is reflected inertia × motor angular acceleration, and torque-producing current is torque divided by the torque constant. Estimated DC bus current is derived from mechanical power (torque × angular velocity), bus voltage, and efficiency; it can be negative during deceleration to represent idealized regeneration. This estimate excludes winding copper losses, cutting force, friction, drive-specific current control, motor thermal limits, and real regenerative-bus behavior. Enabled block graphs are also collected at the end of the pipeline in the Pipeline Graphs section.

Compare related results in a master chart

When two or more enabled graphs sweep the same input name across the same start and end values with the same number of samples, the Studio automatically overlays their data in a master chart in Pipeline Graphs. You do not need to drag charts or manually combine them. This is useful for comparing related quantities as a parameter changes. For example, two frequency-dependent formulas can share a frequency sweep.

The individual block graphs remain available. If outputs use different units, the master chart gives them separately labeled vertical scales; compare the labels and series names rather than comparing heights alone. If no master chart appears, the sweeps are not compatible (for example, the ranges, input, or sample counts differ), or fewer than two usable graph series are enabled.

A sweep is a mathematical exploration, not a safety certification. Ensure the chosen parameter range is physically appropriate before using results to select or operate hardware.

Formula families

Motion and mechanics

Stepper/servo resolution, mechanical resolution, maximum feed rate, cylinder and reflected inertia, inertia ratio, torque for thrust, torque-to-watts, and calibration.

Electrical

DC and AC current, RMS/peak conversions, single- and balanced three-phase real/apparent/reactive power and power factor, grouped-load DC supply sizing, estimated stepper supply current, series RLC impedance/current/phase, reactance, resonance, and stored energy.

Conversions

Length, mass, force, torque, power, steps/mm to steps/inch, and AWG-to-area conversions.

Units to check

For example: wire length in meters, inductance in henries, capacitance in farads, frequency in hertz, and screw lead in millimeters or meters as specified by the selected formula.

The visual block editor accepts numeric inputs. The stepper supply-current block presents its options as individual numeric fields: provide exactly one of phase voltage or winding resistance. Helpers requiring arbitrary arrays or specialized wire options, such as combining a list of PSU loads or choosing an AWG/material for wire-drop calculations, remain available in the JavaScript library but are not yet exposed as blocks.

AC formulas and when to use them

AC formulas below use RMS voltage and current unless the name says peak. RMS values are the effective values normally printed on AC equipment and meters. For a sine wave, peak = RMS × √2.

Current from real power

Single phase: I = P / (V × PF). Balanced three phase: I = P / (√3 × Vline × PF). Use watts, volts RMS, and a power factor from 0 to 1. For example, 1,000 W at 230 V and PF 0.8 is about 5.43 A single-phase.

Real, apparent, and reactive power

Single phase apparent power: S = V × I VA; real power: P = V × I × PF W. Balanced three phase uses S = √3 × Vline × Iline and P = √3 × Vline × Iline × PF. Reactive power magnitude is Q = S × √(1 − PF²) var. The reactive-power helpers return magnitude only, not whether the load is leading or lagging.

Calculate power factor in a formula block

Choose Power factor from single-phase watts, volts, and amps when you know single-phase real power, RMS voltage, and RMS current. For balanced three-phase equipment, choose Power factor from three-phase watts, volts, and amps and enter total real power, line-to-line RMS voltage, and line current. The result is shown as a PF ratio from 0 to 1, with an option to display it as a percentage. For example, PF 0.8 is 80%.

Power factor and series RLC

Power factor is P / S. Series RLC formulas use resistance in ohms, inductance in henries, capacitance in farads, and frequency in hertz: XL = 2πfL, XC = 1/(2πfC), and |Z| = √(R² + (XL − XC)²). The phase-angle helper returns radians: positive is inductive and negative is capacitive.

Three-phase helpers assume a balanced system and use line-to-line RMS voltage with line RMS current. AC current and power calculations based on real power assume sinusoidal quantities and a meaningful power factor; nonlinear loads with harmonic distortion may need true-RMS measurements and more detailed analysis. Ideal RLC results do not include component tolerances, losses, saturation, or parasitic effects.

Account for motor and drive losses

torqueAndRpmToWatts estimates mechanical shaft output. When estimating DC supply demand from that result, place electricalPowerFromShaft between the shaft-power block and the PSU estimate. It divides shaft power by a combined motor/drive efficiency; its 0.8 default is illustrative, not a motor specification. Then apply the PSU efficiency separately in estimateDcSupplyCurrent. These efficiencies describe different conversion losses and should not be combined or counted twice.

Example workflow: shaft power to estimated DC supply current

This example shows how to build a traceable chain without treating every value as if it came from the same place. Use the actual rated or measured values for your hardware; the values below are not a machine recommendation.

  1. Add Motor shaft power from torque and RPM if you know the shaft torque and rotational speed. This estimates mechanical output power in watts.
  2. Add Electrical input power from motor shaft power. Pipe the shaft-power result into its shaft-power input, and replace its illustrative efficiency with a supported motor/drive estimate when available.
  3. Add Estimated DC power-supply current for a load. Pipe electrical input power into load power. Enter the DC supply voltage and PSU efficiency; leave load quantity at one unless the power represents one of several identical groups.
  4. Review the result as a rough supply-current estimate. The motor/drive efficiency and the PSU efficiency account for losses at different stages; do not use the same efficiency twice.
  5. If cable drop matters, add a separate Voltage lost along a DC wire block, using the relevant supply voltage, the load current, one-way wire length, and conductor details. Check the configured voltage-drop advisory and independently verify wire ampacity and installation requirements.

You can branch one upstream result into multiple downstream calculations. The related-calculations group will show that relationship, but each branch still needs the correct units and assumptions.

Review DC cable voltage drop

The Studio compares each dcWireVoltageDrop result with the configurable “Max wire drop” threshold (default 5%). It also displays an advisory above 3% when the configured threshold is higher. These are design-review prompts, not automatic interlocks, universal code limits, or code-compliance determinations. Applicable limits depend on the installation, jurisdiction, equipment, conductor ampacity, temperature, and other conditions. The formula takes one-way distance and includes both conductors in its resistance estimate.

Estimate DC supply current from load ratings

Select estimateDcSupplyCurrent to estimate a PSU's output current for one load group. Enter the group's power in watts, or leave that field blank and enter load voltage and current instead. Set the quantity to the number of identical loads and enter PSU efficiency as a fraction from greater than 0 to 1. The result is total load power ÷ efficiency ÷ supply voltage. This is a sizing estimate; it does not account for startup surges, transient demand, wiring losses, or required design margin. If the load starts as mechanical shaft power, convert it with electricalPowerFromShaft first, then use the result as the load power here.

Interpret the three-phase spindle estimate

threePhaseAcCurrent estimates balanced three-phase line current from real electrical input power, line-to-line voltage, and power factor. In the industrial profile, the 5.5 kW spindle estimate is intentionally independent of the DC positioning-axis chain; it is not summed with the axis power. The estimate does not model spindle-drive harmonics, starting current, unbalance, or other loads.

Estimate stepper DC supply current

Select estimateStepperSupplyCurrent to estimate supply-side current from DC supply voltage and motor phase current. Enter exactly one of phase voltage or winding resistance; the optional energized-phase count defaults to 2 and driver efficiency defaults to 0.9. The estimate uses phase electrical power and does not model a driver’s switching behavior, motion-dependent current, or actual motor/driver losses. Treat it as a rough estimate, not a substitute for the driver manufacturer’s supply-current specifications.

Troubleshooting and common mistakes

The result says “Error”

Hover over or focus the error to read its message. Check that required inputs are filled, numeric, and in the units shown. Look for zero in a denominator, an invalid efficiency, a negative value where only positive values make sense, or a missing Pipe selection.

A Pipe value is missing or the dependent result errors

The producer must be above the consumer. Check that the producer has a usable result name, then open the dependent input’s Pipe menu and select the current output. If you renamed or deleted a producer, reconnect its consumers. Confirm that the output quantity and downstream input have compatible units.

The number looks unexpectedly large or small

Check unit prefixes, degrees versus arcseconds, millimeters versus meters, screw lead versus belt pitch, and whether a value is per phase, per motor, or a total. Confirm that a selected display unit did not lead you to enter a converted value into a field expecting the original unit. Use the converter as a check, not as an automatic input conversion.

The expected graph or combined chart is missing

Turn on the block’s Graph option, choose a numeric input the formula can sweep, and set a minimum lower than the maximum with 2–500 samples. Check that the range is valid for the formula and read any message about omitted samples. A master chart needs at least two compatible valid series; match the swept input, range, and sample count.

The group or role badge changed

Related groups are based on Pipe connections, not on similar formula names. A block can be mathematically related but remain separate if it does not use another block’s output. Check the Pipe menus and the group explanation to understand the current dependency path.

A chart or value seems too precise

Display digits are not a statement of measurement accuracy. Real hardware has tolerances, calibration error, temperature effects, losses, compliance, and operating limits that may not be included in the selected formula. Round conclusions to a precision justified by the input data and assumptions.

Save, load, and share your pipeline

  • Save JSON downloads the current formula blocks, values, result names, Pipe connections, display choices, and graph settings.
  • Load JSON opens a previously saved Studio pipeline. Loading replaces the blocks currently on the canvas; save the current setup first if you need to keep it.
  • Keep the JSON file with project notes or revision information so you can identify the machine, source documents, and assumptions it represents.
  • The JSON file is a pipeline configuration, not a report or a verified engineering record. Review its inputs and recalculate/check results when you load it.
  • The configurable global wire-drop threshold and the standalone reference-chart and quick-converter inputs are not part of the saved formula pipeline. Record those separately if they matter to your review.

Safety and engineering note

These calculations are estimates, not a substitute for manufacturer specifications, qualified engineering review, electrical codes, wire ampacity checks, or machine testing. In particular, stepper phase current is not the same as a driver’s DC supply current, and calculated shaft power is not electrical input power. Use measured or manufacturer-specified efficiencies and check component ratings, conductor ampacity, voltage drop, protective devices, and applicable codes before building or operating equipment.
